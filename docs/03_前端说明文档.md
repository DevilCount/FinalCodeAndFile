## 1. 前端架构概述

### 1.1 架构设计

前端采用 **Vue 3 + Vite** 单页应用（SPA）架构，使用 **组件化开发** 模式，通过 **Vue Router** 管理路由，**Pinia** 进行状态管理。

### 1.2 架构图

```
┌─────────────────────────────────────────────────────────┐
│                     用户界面层                            │
│  (Login.vue / Register.vue / Dashboard.vue / ...)      │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│                   组件层 (Components)                    │
│              (Layout.vue / 业务组件)                    │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│                   服务层 (Services)                      │
│    (userService.js / sampleService.js / ...)            │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│                   工具层 (Utils)                         │
│        (formatDate / formatNumber / ...)               │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│                   路由层 (Router)                        │
│              (路由配置 / 路由守卫)                       │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│                   状态管理 (Pinia)                       │
│              (全局状态 / 组件状态)                       │
└─────────────────────────────────────────────────────────┘
```

### 2.4 为什么选择这些技术？

**Vue 3 Composition API：**
- 更好的代码组织和复用
- TypeScript支持更好
- 更小的打包体积
- 更好的运行时性能

**Vite：**
- 极速的冷启动
- 即时的热模块替换（HMR）
- 原生ES模块支持
- 优化的构建输出

**Element Plus：**
- 完整的组件库
- 优秀的中文文档
- 活跃的社区支持
- 完善的TypeScript支持

#### 4.1.3 路由守卫

路由守卫实现了以下功能：

1. **页面标题设置**
   - 自动设置 `document.title`
   - 格式：`{页面标题} - {应用标题}`

2. **登录验证**
   - 检查 `localStorage` 中的 token
   - 未登录用户跳转到登录页
   - 登录用户可访问受保护页面

```javascript
router.beforeEach((to, from, next) => {
  document.title = `${to.meta.title} - ${import.meta.env.VITE_APP_TITLE}`
  
  if (to.meta.requiresAuth) {
    const token = localStorage.getItem('token')
    if (!token) {
      next({ name: 'Login' })
    } else {
      next()
    }
  } else {
    next()
  }
})
```

### 4.2 服务层（Services）

#### 4.2.1 设计原则

服务层采用以下设计原则：

1. **单一职责**
   - 每个服务只负责一个业务模块
   - userService - 用户相关
   - sampleService - 标本相关
   - reportService - 报告相关
   - aiService - AI诊断相关

2. **统一接口**
   - 使用 axios 创建统一的实例
   - 统一的请求/响应拦截器
   - 统一的错误处理

3. **Token管理**
   - 请求拦截器自动添加 Authorization header
   - 从 localStorage 获取 token

#### 4.2.2 Axios 实例配置

```javascript
const instance = axios.create({
  baseURL: API_BASE_URL,
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json'
  }
})
```

#### 4.2.3 请求拦截器

```javascript
instance.interceptors.request.use(
  config => {
    const token = localStorage.getItem('token')
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config
  },
  error => {
    return Promise.reject(error)
  }
)
```

#### 4.2.4 响应拦截器

```javascript
instance.interceptors.response.use(
  response => {
    return response.data
  },
  error => {
    console.error('API请求错误:', error)
    return Promise.reject(error)
  }
)
```

### 5.2 组件通信方式

#### 5.2.1 Props / Events

父子组件通信使用 Props 和 Events：

```vue
<!-- 父组件 -->
<ChildComponent :data="parentData" @event="handleEvent" />

<!-- 子组件 -->
<script setup>
const props = defineProps(['data'])
const emit = defineEmits(['event'])

const triggerEvent = () => {
  emit('event', payload)
}
</script>
```

#### 5.2.2 Provide / Inject

跨层级组件通信使用 Provide / Inject：

```vue
<!-- 祖先组件 -->
<script setup>
import { provide } from 'vue'
provide('key', value)
</script>

<!-- 后代组件 -->
<script setup>
import { inject } from 'vue'
const value = inject('key')
</script>
```

#### 5.2.3 Pinia 状态管理

全局状态使用 Pinia：

```javascript
// store
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', {
  state: () => ({
    user: null
  }),
  actions: {
    setUser(user) {
      this.user = user
    }
  }
})

// 组件中使用
<script setup>
import { useUserStore } from '@/stores/user'
const userStore = useUserStore()
</script>
```

### 5.3 表单验证

使用 Element Plus 内置的表单验证：

```vue
<template>
  <el-form :model="form" :rules="rules" ref="formRef">
    <el-form-item prop="username">
      <el-input v-model="form.username" />
    </el-form-item>
  </el-form>
</template>

<script setup>
const rules = {
  username: [
    { required: true, message: '必填', trigger: 'blur' },
    { min: 3, max: 20, message: '长度3-20', trigger: 'blur' }
  ]
}
</script>
```

## 6. 开发指南

### 6.1 环境准备

#### 6.1.1 开发环境要求

- Node.js 16+
- npm 7+ 或 yarn 1.22+

#### 6.1.2 安装依赖

```bash
cd frontend
npm install
```

### 6.2 开发流程

#### 6.2.1 启动开发服务器

```bash
npm run dev
```

访问：http://localhost:3000

#### 6.2.2 代码规范

**命名规范：**
- 组件名：PascalCase（如 `UserList.vue`）
- 文件名：kebab-case（如 `user-list.vue`）
- 变量名：camelCase（如 `userName`）
- 常量名：UPPER_SNAKE_CASE（如 `API_BASE_URL`）

**代码风格：**
- 使用 2 空格缩进
- 使用单引号
- 语句末尾不加分号
- 使用 Composition API

### 6.3 创建新页面

#### 6.3.1 创建页面组件

在 `src/views/` 下创建新的页面组件：

```vue
<!-- src/views/module/PageName.vue -->
<template>
  <div class="page-container">
    <h2>页面标题</h2>
  </div>
</template>

<script setup>
// 页面逻辑
</script>

<style lang="scss" scoped>
.page-container {
  // 页面样式
}
</style>
```

#### 6.3.2 配置路由

在 `src/router/index.js` 中添加路由：

```javascript
{
  path: 'module/page',
  name: 'ModulePage',
  component: () => import('../views/module/PageName.vue'),
  meta: { title: '页面标题' }
}
```

#### 6.3.3 添加菜单

在 `Layout.vue` 中添加菜单项：

```vue
<el-menu-item index="/module/page">
  <el-icon><IconName /></el-icon>
  <span>菜单项</span>
</el-menu-item>
```

### 6.4 调用API

#### 6.4.1 创建服务文件

在 `src/services/` 中创建服务文件：

```javascript
// src/services/xxxService.js
import axios from 'axios'

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL

const instance = axios.create({
  baseURL: API_BASE_URL,
  timeout: 10000
})

const xxxService = {
  list: () => instance.get('/xxx/list'),
  get: (id) => instance.get(`/xxx/${id}`),
  create: (data) => instance.post('/xxx/create', data),
  update: (id, data) => instance.put(`/xxx/${id}`, data),
  delete: (id) => instance.delete(`/xxx/${id}`)
}

export default xxxService
```

#### 6.4.2 在组件中使用

```vue
<script setup>
import { ref, onMounted } from 'vue'
import xxxService from '@/services/xxxService'
import { ElMessage } from 'element-plus'

const dataList = ref([])
const loading = ref(false)

const fetchData = async () => {
  loading.value = true
  try {
    const res = await xxxService.list()
    dataList.value = res.data
  } catch (error) {
    ElMessage.error('获取数据失败')
  } finally {
    loading.value = false
  }
}

onMounted(() => {
  fetchData()
})
</script>
```

## 7. 常见问题

### 7.1 开发问题

**Q: 开发服务器启动失败？**

A: 检查端口3000是否被占用，可在 `vite.config.js` 中修改端口：

```javascript
server: {
  port: 3001  // 修改为其他端口
}
```

**Q: API请求404？**

A: 检查：
1. 后端服务是否启动
2. `.env` 中的 `VITE_API_BASE_URL` 是否正确
3. `vite.config.js` 中的代理配置是否正确

**Q: 热更新不生效？**

A: 尝试：
1. 重启开发服务器
2. 清除浏览器缓存
3. 检查文件命名是否正确

### 7.2 样式问题

**Q: 样式不生效？**

A: 检查：
1. 是否使用了 `scoped` 属性
2. 样式选择器是否正确
3. 样式文件是否正确导入

**Q: Element Plus 样式冲突？**

A: 使用深度选择器：

```scss
:deep(.el-button) {
  // 自定义样式
}
```

### 7.3 路由问题

**Q: 刷新页面404？**

A: 这是 History 模式的问题，生产环境需要配置服务器：

**Nginx 配置：**
```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

**Q: 路由跳转后页面空白？**

A: 检查：
1. 路由组件是否正确导出
2. 路由路径是否正确
3. 是否有 JavaScript 错误
