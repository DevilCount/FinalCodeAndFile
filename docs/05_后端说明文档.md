## 1. 后端架构概述

### 1.1 整体架构

本系统采用 **Spring Cloud Alibaba** 微服务架构，包含以下核心组件：

```
┌─────────────────────────────────────────────────────────┐
│                        前端应用                            │
└────────────────────────────┬────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────┐
│                    API Gateway (8080)                     │
│              Spring Cloud Gateway + Nacos                  │
└────────────────┬────────────────┬─────────────────────────┘
                 │                │
        ┌────────┴────────┐       │
        ▼                 ▼       ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ User Service │  │ Sample Svc   │  │ Report Svc   │
│   (8081)     │  │   (8082)     │  │   (8083)     │
└──────────────┘  └──────────────┘  └──────────────┘
        │                 │                 │
        └────────────────┴─────────────────┘
                          │
                          ▼
                 ┌──────────────┐
                 │   Nacos      │
                 │  (8848)      │
                 └──────────────┘
                          │
                          ▼
                 ┌──────────────┐
                 │   MySQL      │
                 │  (3306)      │
                 └──────────────┘
```

### 1.2 架构特点

- **服务注册与发现**：使用 Nacos 作为服务注册中心
- **API 网关**：使用 Spring Cloud Gateway 统一路由入口
- **负载均衡**：通过 Ribbon 实现客户端负载均衡
- **数据持久化**：使用 MyBatis Plus 简化数据库操作
- **配置管理**：支持 Nacos 配置中心（可选）

### 1.3 服务间通信

- **同步通信**：使用 OpenFeign 进行服务间调用
- **异步通信**：预留扩展接口，可集成消息队列

## 4. 核心模块说明

### 4.1 公共模块 (lab-common)

#### 4.1.1 统一返回结果 (Result)

**位置**：`lab-common/src/main/java/com/sunyaxin/common/result/Result.java`

**功能**：定义统一的 API 响应格式

```java
{
    "code": 200,           // 状态码
    "message": "操作成功", // 提示信息
    "data": {...},         // 响应数据
    "timestamp": 1234567890 // 时间戳
}
```

**静态方法**：
- `success()` - 成功响应（无数据）
- `success(data)` - 成功响应（带数据）
- `success(message, data)` - 成功响应（自定义消息）
- `error()` - 失败响应
- `error(message)` - 失败响应（自定义消息）

#### 4.1.2 实体类 (Entity)

**位置**：`lab-common/src/main/java/com/sunyaxin/common/entity/`

## 5. API 接口说明

### 5.1 统一响应格式

所有 API 接口均返回统一的 JSON 格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1234567890123
}
```

**状态码说明**：
- `200` - 成功
- `400` - 请求参数错误
- `401` - 未授权
- `403` - 禁止访问
- `404` - 资源不存在
- `500` - 服务器内部错误

### 5.2 用户服务接口

#### 5.2.1 用户注册

**接口**：`POST /api/user/register`

**请求参数**：
```json
{
  "username": "string",
  "password": "string",
  "realName": "string",
  "role": "ADMIN|DOCTOR|TECHNICIAN"
}
```

**响应示例**：
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "id": 1,
    "username": "testuser",
    "realName": "测试用户",
    "role": "DOCTOR"
  }
}
```

#### 5.2.2 用户登录

**接口**：`POST /api/user/login`

**请求参数**：
```json
{
  "username": "string",
  "password": "string"
}
```

**响应示例**：
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "id": 1,
    "username": "admin",
    "realName": "管理员",
    "role": "ADMIN"
  }
}
```

#### 5.2.3 获取用户列表

**接口**：`GET /api/user/list`

**响应示例**：
```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "id": 1,
      "username": "admin",
      "realName": "管理员",
      "role": "ADMIN"
    }
  ]
}
```

### 5.3 标本服务接口

#### 5.3.1 创建标本

**接口**：`POST /api/sample/create`

**请求参数**：
```json
{
  "sampleNo": "string",
  "patientName": "string",
  "sampleType": "string",
  "testItems": "string",
  "status": "RECEIVED"
}
```

#### 5.3.2 获取标本列表

**接口**：`GET /api/sample/list`

**查询参数**：
- `status` - 标本状态（可选）
- `keyword` - 搜索关键词（可选）

#### 5.3.3 获取标本详情

**接口**：`GET /api/sample/{id}`

#### 5.3.4 更新标本状态

**接口**：`PUT /api/sample/{id}/status`

**请求参数**：
```json
{
  "status": "TESTING|COMPLETED|ABORTED",
  "operator": "string",
  "remark": "string"
}
```

## 7. 开发指南

### 7.1 环境要求

- **JDK**：17 或更高版本
- **Maven**：3.6+
- **MySQL**：8.0+
- **Nacos**：2.2.3+

### 7.2 环境搭建步骤

#### 7.2.1 安装并启动 Nacos

```bash
# 下载 Nacos
# 解压后进入 bin 目录
cd nacos/bin

# Windows 启动
startup.cmd -m standalone

# 访问控制台
# http://localhost:8848/nacos
# 默认账号密码：nacos/nacos
```

#### 7.2.2 创建数据库

```bash
# 登录 MySQL
mysql -u root -p

# 执行初始化脚本
source d:/FinalCodeAndFile/lab-management-system/sql/init.sql
```

#### 7.2.3 修改数据库配置

编辑各服务的 `application.yml`，修改数据库连接信息：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/lab_management
    username: your_username
    password: your_password
```

#### 7.2.4 编译项目

```bash
# 在项目根目录执行
mvn clean install -DskipTests
```

#### 7.2.5 启动服务

**启动顺序**：
1. lab-gateway
2. lab-user-service
3. lab-sample-service
4. lab-report-service
5. lab-ai-service
6. lab-hl7-service

**启动方式**：
```bash
# 方式一：IDE 中直接运行 Application 主类
# 方式二：命令行启动
cd lab-user-service
mvn spring-boot:run
```

### 7.3 新增微服务模块

#### 7.3.1 创建新模块

1. 在父项目 `pom.xml` 中添加模块：
```xml
<modules>
    ...
    <module>lab-new-service</module>
</modules>
```

2. 复制现有服务模块作为模板，修改配置

3. 更新网关路由配置

### 7.4 代码规范

#### 7.4.1 命名规范

- **包名**：全小写，使用点分隔
- **类名**：大驼峰命名法（PascalCase）
- **方法名**：小驼峰命名法（camelCase）
- **常量名**：全大写，下划线分隔

#### 7.4.2 分层规范

- **Controller**：接收请求，参数校验，调用 Service
- **Service**：业务逻辑处理
- **Mapper**：数据库操作
- **DTO/VO**：数据传输对象

### 7.5 调试技巧

#### 7.5.1 查看服务注册状态

访问 Nacos 控制台：`http://localhost:8848/nacos`

查看服务列表 → 服务管理 → 服务列表

#### 7.5.2 网关日志调试

## 8. 常见问题

### 8.1 服务启动失败

**问题**：服务启动时提示无法连接到 Nacos

**解决方案**：
1. 确认 Nacos 已启动
2. 检查 `application.yml` 中的 Nacos 地址配置
3. 确认防火墙未阻止 8848 端口

### 8.2 数据库连接失败

**问题**：提示 `Communications link failure`

**解决方案**：
1. 确认 MySQL 服务已启动
2. 检查数据库连接配置（URL、用户名、密码）
3. 确认数据库 `lab_management` 已创建
4. 检查时区配置，添加 `serverTimezone=Asia/Shanghai`

### 8.3 网关路由失败

**问题**：访问网关接口提示 404

**解决方案**：
1. 确认目标服务已注册到 Nacos
2. 检查网关路由配置是否正确
3. 确认请求路径是否匹配路由规则
4. 查看网关日志，确认路由转发情况

### 8.4 跨域问题

**问题**：前端调用接口时提示跨域错误

**解决方案**：
网关已配置跨域支持，如仍有问题：
1. 检查网关的 CORS 配置
2. 确认前端请求的域名和端口在允许列表中

### 8.5 MyBatis Plus 报错

**问题**：提示 `Invalid bound statement (not found)`

**解决方案**：
1. 确认 Mapper 接口上有 `@Mapper` 注解
2. 确认 Mapper XML 文件位置正确
3. 检查 `application.yml` 中的 MyBatis Plus 配置

### 8.6 端口被占用

**问题**：启动时提示端口已被占用

**解决方案**：
1. 查找占用端口的进程：
   ```bash
   netstat -ano | findstr "8080"
   ```
2. 结束进程或修改服务端口配置

### 8.7 Maven 依赖下载失败

**问题**：Maven 编译时依赖下载失败

**解决方案**：
1. 检查网络连接
2. 配置 Maven 镜像（阿里云镜像）
3. 清理本地仓库：`mvn clean`
4. 强制更新依赖：`mvn clean install -U`
